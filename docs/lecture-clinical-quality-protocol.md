# Clinical verification and release protocol

Effective October 31, 2026. Applies to new lectures, clinical revisions, separate drafts, and approved audit corrections. Use with [the lecture link protocol](lecture-link-protocol.md). The October 31 audit exposed stale source rules, lost qualifications, incorrect classification, cross-module contradictions, and draft writes reported complete before they were saved.

This protocol defines required editorial work. It is not an automated medical fact checker. Existing link checks enforce file hashes and navigation records; they do not verify clinical evidence. Do not describe these new editorial requirements as CI-enforced checks.

## 1. Define and verify the clinical claims

Before finalizing teaching, identify each consequential claim in scope: treatment eligibility, diagnostic interpretation/performance, agent selection, dose/route/duration, contraindications, interactions, monitoring, resistance interpretation, and follow-up. For a new lecture cover all such claims. For a revision cover changed claims and any unchanged prerequisite or companion statement affected by them. A full periodic review uses the entire current catalog.

Keep a compact evidence record in the private review response or review artifact. Identical repeated claims may share one record, but each independently actionable statement in a table or sentence must be accounted for. For each claim record:

| Required field | What must be recorded |
| --- | --- |
| Claim and location | Exact proposed statement and module section/table/case |
| Source | Public primary-source URL and actual section, recommendation, table, or label subsection |
| Currency and access | Source publication/update version, date accessed, and full-text/table/abstract-only access |
| Scope | Population, species, infection site, severity and treatment phase actually supported |
| Qualifications | Material exclusions, special populations, uncertainty, and recommendation strength |
| Disposition | Supported; revised to match evidence; omitted; or unresolved with the specific limit |

Open the source and read the relevant passage. Search snippets, an abstract, or a guideline landing page cannot verify a claim that depends on an inaccessible table or full-text qualification. Check for newer issuing-organization guidance, label changes, corrections and retractions before carrying an existing rule forward. If a source is undated, record that and the access date; do not invent an update date.

Do not initialize records by claiming all existing content was reverified. Do not publish an unsupported actionable recommendation as established fact. Narrow or omit it, or state the unresolved evidence explicitly. Precise sensitivity/specificity requires an identified assay, specimen, population and setting; a broad range must be identified as approximate.

## 2. Review the final wording for exceptions

After drafting, perform a separate verification pass with the actual primary sources reopened. Use a separate reviewer when available. The reviewer must challenge the wording, not accept the writer's references or completion labels.

Ask whether a patient could receive the wrong decision from the sentence because it omits:

- A species, syndrome, site, severity, or immune-status distinction.
- Initial versus transition versus suppressive therapy.
- Pregnancy, renal/hepatic impairment, or an age restriction.
- The actual formulation, component dose, route, or fixed-pack restriction.
- The difference between FDA labeling, guideline-supported off-label use, and local practice.
- The difference between an MIC, an available interpretive breakpoint, and clinical effectiveness.

Check categorical words such as "always," "never," "contraindicated," "preferred," and "does not treat" against the source's actual scope. Do not flatten mechanisms or risk groups into a mnemonic when their evidence differs. Consider contraindications and exceptions alongside the main recommendation, not only in a distant footnote.

Record who or what performed this second pass and the unresolved questions. Another AI pass is an additional error search, not faculty/pharmacy endorsement or proof of independent clinical judgment. Request focused specialist input when an unresolved clinical distinction needs it; do not mark that input completed unless obtained. Authorization already given for an edit remains valid.

## 3. Reconcile every occurrence

Search each affected claim across the module's main prose, tables, cases, answers, mnemonics, captions, printable summaries, and relevant companion lectures. Check separate draft copies included in the task as distinct release targets. A changed main paragraph does not establish that its summary is corrected.

Record which repeated occurrences and companion sections were changed or deliberately retained, and why. Preserve links and anchors through the existing link protocol. Review all affected dose components and qualifiers together. Do not update a general source-review date when only a limited claim or presentation element was checked.

## 4. Verify each final target before reporting completion

List the intended targets before writing, using the exact repository paths or existing draft-file identities. Follow the owning tool/skill's version and writeback rules; preserve identities and guard against concurrent edits.

For every target, verify the consequential replacement and required educational notice in the final bytes. Check screen and print placement, links and anchors, and mobile rendering when available. Report unavailable browser checks as unavailable.

Correlate every save result with its exact target and resulting version or repository revision. A successful website commit does not verify a separate draft save. If a write result does not establish which final bytes/version were accepted, inspect the saved target before marking it complete. Any later edit requires repeating the affected checks.

For website releases run the repository's applicable preparation, validation and link checks. Verify the deployment belongs to the intended commit, then check the changed claims on the live pages when accessible. Record separately if deployment succeeded but live-page inspection was unavailable.

Use explicit states such as pending, checked in draft, saved, deployed, and live checked. These states describe artifacts, not clinical certification. A draft remains unpublished unless publication was requested and completed.

## 5. Report the observed result and retain open work

Write release notes and the completion response after inspecting all save/deployment results. Report applied changes, exact reviewed scope, remaining uncertainty and failed/unverified targets. Do not turn planned work into a completed claim. Do not say "everything is correct" or imply every source was accessible.

Retain unresolved proposals in the review conversation and carry them into the next appropriate review. Keep the existing every-three-week catalog review and its owner-approval boundary. Scheduled reviews remain read-only until the owner approves the proposed clinical changes; this protocol does not authorize automatic clinical updates or require repeated approval for already-authorized work.

For each release, the compact record should contain the evidence rows, second-pass findings, repeated-location reconciliation, and final target/version outcomes. Keep it with the review rather than adding clinical process notes, private materials, or unverified endorsement to the public teaching pages.
